# Task 2 — Modular operating systems

Read src/contracts.ts and docs/design.md. Own src/modules/farm.ts plus inventory.ts, capacity.ts, time.ts, growth.ts, market.ts, farm-view.ts and tests/farm.test.ts. No other edits/commits. No subagents. Root owns engine and integration.

Export farmModules: ModuleDefinition[] from farm.ts. Split responsibilities into real module definitions, not giant switch. Use IDs/capabilities below; all versions 1.0.0, apiVersion/stateVersion 1 unless a test intentionally migrates.

1. capacity.slots, capacity.physical, capacity.combined: provide capacity@1.0.0. Stateless; query check {items: Array<{id,quantity,weight,volume,length}>, limits: {slots?,maxWeight?,maxVolume?,maxLength?}} -> {allowed:boolean, reason:string}. slots counts distinct positive stacks (not pieces); physical sums weight/volume and longest item, combined enforces both. Explicit g/ml/mm units. Use JSON schemas and safe numeric validation. They can migrate each other's {} states explicitly.
2. inventory.basic: provides inventory@1.0.0, requires capacity ^1.0.0. Config {items: Record<itemId,{name,weight,volume,length}>, containers: Record<containerId,{limits,items:Record<itemId,quantity>}>}. State holds containers and their counts. commands add/remove {container,item,quantity} and transfer {from,to,item,quantity}; query list {container} -> {items:[{id,name,quantity,weight,volume,length}],limits}; query count {container,item}->{quantity}. A failed transfer does not remove source or affect destination. validate all counts, references and capacity. Single inventory provider can own player + warehouse; instances bind independently. No other module writes inventory state.
3. time.step and time.continuous: provide time@1.0.0; state {elapsedSeconds:0}; step config {secondsPerStep:86400}, advance {steps} whole positive -> elapsed; continuous config {}, advance {seconds} positive finite -> elapsed. Both query now {} -> {elapsedSeconds}; emit time.advanced {deltaSeconds,elapsedSeconds}. Both explicitly migrate each other's elapsedSeconds state. No actual timers/Date.now inside them.
4. growth.linear: provide growth-rule@1.0.0; config {multiplier:1}; query progress {deltaSeconds,durationSeconds} -> {amount}; multiplier optional environmental modifier is independent rule implementation, never hardcoded host. Optional extra module growth.greenhouse same contract with configured multiplier and explicit stateless migration to show replacement.
5. planting.basic: provides planting@1.0.0; requires inventory, time, growth-rule ^1.0.0. Config {container:'player',crops:Record<cropId,{name,seedItem,harvestItem,durationSeconds,yield}>}. state {plots:Record<plotId,{crop,progress:number}>}. plant {plot,crop} consumes 1 seed; harvest {plot} only progress>=1, adds yield and clears plot atomically. Query plots returns structured plots including names/progress. On time.advanced respond ONLY to bound time provider (use query time now and event-source check; context lacks provider API so request root if needed, do not assume instance name). Compute delta through growth-rule. Alternative is include clock current values and compare authoritative bound time progress stored to derive delta; ensure unrelated time event doesn't advance. Save all needed last elapsed state. Validation ensures crop IDs, no invalid fractions and known plots.
6. market.fixed: provides market@1.0.0; requires inventory. Config {container:'player',prices:Record<itemId,number>,initialCoins:number}; state {coins:number}; sell {item,quantity} removes inventory and credits coins; query balance -> {coins}. No negative/NaN/unknown-price values.
7. view.farm.text: provides text-view@1.0.0, requires inventory/time/planting/market. Config {title,container:'player'}; query render -> {title,lines:string[]}. Only reads public queries; no simulation state. Chinese output clear plain text.

All interfaces use public context. Commands return JSON values and throw via ctx.fail on meaningful failure. Define config/state/input schemas; make assumptions explicit.
