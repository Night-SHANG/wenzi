Read src/contracts.ts and docs/design.md. Own src/modules/adventure.ts, random.ts, tactics.ts, narrative.ts, tactics-view.ts, tests/adventure.test.ts. No other edits/commits/subagents. Export adventureModules: ModuleDefinition[] from adventure.ts. Engine is being built concurrently. Root authors worlds/CLI against your declared contracts.

Keep host free of gameplay. Implement these modules through public capability calls, with JSON config/state/command schemas and meaningful Chinese errors.

- random.seeded: provide random@1.0.0, config {seed:integer}; state {value: uint32}; command next {} -> {value:number in [0,1)}. Use documented xorshift32 (substitute nonzero seed constant for 0, preserve seed semantics explicitly). Save/restore reproduces future stream; only module owns RNG state. No Math.random/Date.now.
- tactics.grid: provides tactics@1.0.0, requires random ^1.0.0. Config {width,height,movePoints:integer,units:Array<{id,name,side:'player'|'enemy',x,y,hp,damage,hitChance}>}. State {turn:number,side,units:Array<...plus remainingMove>}. commands move {unit,x,y} orthogonal Manhattan distance within remaining allowance, in-bounds, empty target; attack {unit,target} adjacent enemy, acting side, alive; consumes action once per unit per turn (explicit acted field), calls random.next and applies damage if roll<hitChance; endTurn {} switches side, increments turn and resets incoming side. Preserve dead units but disallow actions on them; do not conflate movement and attack expenditure. query board -> {width,height,turn,side,units,winner:null|'player'|'enemy'}. Result/terminal rules should reject play after winner. Opponent can be operated with same CLI (no AI promised).
- view.tactics.text: provide text-view, require tactics; query render -> {title,lines:string[]} with grid text + living units/turn. Separate from rules, no DOM.
- narrative.branching: provides narrative@1.0.0; config {start:string,nodes:Record<string,{text:string,choices:Array<{id,label,next}>}>}; state {node:string,visits:number}; choose {choice} follows valid choice, visit++ and emit narrative.changed. query scene -> {node,text,choices,visits}; validate graph IDs, start/next references and duplicate choice IDs. No time/inventory dependency.
- view.narrative.text: provide text-view, require narrative; query render -> {title,lines} from scene.

Tests before implementation: narrative runs alone (with view), invalid choice rollback; wrong turn/out of range/occupied movement fail; legal battle advances/terminal guard; deterministic sequence survives save/load and failed command cannot spend RNG; arbitrary module identifiers work without core change. Small world configs in tests only; root will create world JSON. Record exactly what is tested vs not tested in docs/tasks/adventure-report.md.
