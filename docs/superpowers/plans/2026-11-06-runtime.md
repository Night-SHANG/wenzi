# Modular Text World Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement the assigned task. The user explicitly authorizes parallel independent work; shared contracts are frozen before dispatch.

**Goal:** Deliver a reusable running modular host, interchangeable example systems, three world assemblies, author CLI, and truthful test evidence.

**Architecture:** TypeScript public contracts and synchronous single-authority transactions. Gameplay, clocks, random rules and text views are public modules. JSON world packages bind capabilities to instances; snapshot upgrades build a new instance before switching.

**Tech Stack:** Node >=24.12.0, TypeScript 5.9.3, Ajv 8.17.1, semver 7.8.5, node:test.

**Spec:** docs/design.md and src/contracts.ts.

## Global Constraints

- All existing and future systems are modular; examples never restrict the extension domain.
- No gameplay imports or hardcoded gameplay types in src/engine.
- Core, modules and CLI operate on the same public contracts; no privileged built-ins.
- Only trusted local code is supported; never claim hostile-code sandboxing, MMO scale, or a finished game.
- No gameplay source copied from third parties without preserving its actual licence/provenance.
- Independent directories may be implemented concurrently; only root commits to avoid shared-index races.
- Tests exercise actual behaviour, including failures; proposals are never recorded as passed tests.

## Review Focus

- Duplicate requests or transaction failure must not duplicate/loss resources or events (Tasks 1, 2).
- Unknown capability/provider, malformed state and ambiguous bindings reject before running (Task 1).
- Non-finite/negative quantities and incompatible time units reject clearly (Tasks 1, 2, 3).
- Save restore and replacement preserve authoritative state; failed migration leaves old instance intact (Tasks 1, 4).
- A third-party module of an unanticipated type runs unchanged through the same host (Tasks 1, 4).
