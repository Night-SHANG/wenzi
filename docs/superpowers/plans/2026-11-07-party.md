# v0.8 Party and Multiple-Target Battles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. User has already requested continuous parallel execution without repeated design/permission handoffs. Steps use checkbox tracking; root owns Git staging and commits.

**Goal:** Deliver a persistent companion party with interchangeable initiative and targeting, integrated leader skills, rewards, quests, recovery, authoring and verified source publication.
**Architecture:** New party-battle/combat-action/encounter-records contracts preserve the legacy duel contract. A shared battle-session coordinates controllers; party delegates leader HP and owns only companion HP. Existing host and dependencies stay unchanged.
**Tech Stack:** Node >=24.12.0, TypeScript, existing Ajv/semver/fast-json-patch.
**Spec:** docs/superpowers/specs/2026-11-07-party-design.md (binding; read full before implementation).

## Global Constraints

Read AGENTS.md and the complete spec. All module IDs, exported names, input/output fields and state ownership in the spec are binding. Root alone stages/commits and edits registry/worlds/shared docs. Workers do not spawn agents or run global suites/builds; use focused node --test commands and record genuine RED/GREEN. Root runs full Preflight/build/runtime after independent owners and scoped reviews are stable. No src/engine or src/contracts.ts edits, no new dependencies. IDs use Unicode code points; queries pure; failed nested commands restore complete snapshots. Counts are safe integers and clocks are cumulative simulation seconds. Legacy worlds preserve behavior and saves migrate only from explicitly supported identities. All independent policies remain replaceable.

## Review Focus

- Two controllers using the same actors must share the same explicit battle-session; non-null battle phases keep the lease and bad direct releases roll back (Task3).
- A malformed enemy AI/HP provider after earlier writes must roll back all allied/enemy HP and the turn queue (Task3).
- Special/astral IDs may collide across party/enemy namespaces but never select the wrong actor (Tasks1–3).
- Current rules must validate even while recruited members/current enemies/rewards/order remain frozen after edits or deletions (Tasks1–3).
- Existing skill cooldowns and accepted quest baselines survive version upgrades; the new path must not reinterpret singular enemyHp as a group (Task4).
