# Campaign Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Execute the already-authorized batch continuously; three disjoint implementation owners run in parallel and root alone owns Git staging/commits and final integration.

**Goal:** Deliver a repeatable exploration/combat/production/quest/progression world and repair the three known generic input/view limits in the same verified batch.

**Architecture:** Ten ordinary module definitions use existing capability bindings and host transactions. Inventory, currency, time, save format and authoring stay shared. Independent content/policy providers remain replaceable; already accepted work freezes its terms.

**Tech Stack:** TypeScript, Node.js >=24.12.0, existing Ajv/semver/JSON Patch dependencies only.

**Spec:** docs/superpowers/specs/2026-11-07-campaign-design.md

## Global Constraints

- 全部现有和未来系统、规则、数据、内容、表现、界面与操作都遵守模块化；本批样例不限定范围。
- 所有新定义 version=1.0.0、apiVersion=1、stateVersion=1，能力版本 1.0.0。
- 所有实例只写自身状态，嵌套调用加入宿主事务；不能用隐藏全局状态或第二套物品/金币账目。
- 计数为非负安全整数，正数操作不能为零；ID 遵守现有 idSchema 并支持特殊对象键。
- 任意外部能力返回都要核验消费字段、身份和数值，不能仅用 TypeScript 类型断言。
- No edits to src/engine or src/contracts.ts, no new dependencies. Use capacity.ts helpers and simulation-time.ts; do not create another schema/transaction/persistence framework.
- Each owner changes only its listed files, runs focused tests, writes its report, and leaves Git index/commits to root. Root runs the complete Preflight/build/runtime gates once after integration.
- Keep Chinese player messages. Independent scope reviews follow owner completion; fresh broad review follows integration. Do not re-run another worker's unchanged suite.

## Review Focus

1. Frozen rewards after catalog deletion and replacement must preserve pending paid/won work; test current-catalog invalidity separately.
2. Failure late in a multi-resource reward or after XP award must restore the complete snapshot, including victory/job/quest state, counters and event history.
3. New/repeated quests must use acceptance baselines; historical victories cannot satisfy them, and replacing counters with lower values must reject.
4. External providers can return malformed numbers, mismatched IDs or special keys; consumers reject before committing, with read-only views/queries unchanged.
5. Saved active/terminal battles and generic CLI JSON commands must survive restore, including spaces/quotes in instance IDs and early --json errors.
